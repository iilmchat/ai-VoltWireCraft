## 1. Контекст

### 1.1 Точка старта

**Релиз:** `v0.5.0` опубликован; 242 теста и 312 smoke-проверок зелёные.
Закрыты `KI-001`…`KI-007`, реализованы трёхфазная сборка, конвертация DWG,
шесть шаблонов и lazy-загрузка 3D.
**Продукт:** САПР электрических сетей 0,4 кВ и сборки щитов НКУ для ИЖС,
квартир и коммерческой недвижимости.
**Стек:** NestJS 12, React 19 + Vite + Konva.js + Tauri, Three.js,
Python/FastAPI, PostgreSQL 17 + pgvector, Drizzle ORM.
**Документы:** RULES v1.0.0, `DESIGN_V050`, `PUE_RULES_V02.md`,
`PUE_SHORT_CIRCUIT_V03.md`, `TCC_SELECTIVITY_V06.md`.

### 1.2 Проблема

Текущая модель предполагает один щит на объект. Коттеджи и офисы имеют
иерархию `ВРУ → ЩР` с магистральными линиями; без неё невозможно корректно
посчитать суммарную потерю напряжения и проверить, что вышестоящий аппарат
не сработает раньше нижестоящего. Существующая проверка `1,6 · I_n` — только
упрощённая токовая оценка, она не учитывает время-токовые характеристики.

### 1.3 Новые возможности

| Возможность | Обозначение | Что делает |
|---|---|---|
| Иерархия щитов | `parentPanelId`, `panelRole`, `feeder_line` | Связывает ВРУ, ЩР и щит освещения в дерево проекта |
| Каскадный расчёт | $\Delta U_{сумм}$ | Суммирует потери магистрали и групповых линий, предел 5 % |
| Движок ВТХ | `selectivity-tcc` | Кусочно-аналитические кривые B/C/D, предельная селективность $I_s$ |
| Проверка Icn | $I_{cn} \ge I_{кз}$ | Сверка отключающей способности с током КЗ в точке установки |
| Селектор щита | UI | Один граф, контекст активного щита для всех проекций |

### 1.4 Продуктовые сценарии

1. Двухэтажный дом: ВРУ на вводе питает ЩР первого и второго этажа;
   суммарная потеря напряжения по магистрали и группе ≤ 5 %.
2. Аудит показывает, что вводной автомат B32 работает раньше группового C16
   при токе КЗ; инженер меняет кривую или номинал.
3. В инспекторе аппарата открывается график ВТХ с точками 1,13/1,45/2,55 $I_n$
   и зонами мгновенного срабатывания.
4. Переключение активного щита меняет 2D-компоновку, 3D-сцену и схему
   без изменения графа.

### 1.5 Цели и критерии успеха

- Иерархия сохраняется в `ProjectGraphSchema` v2 без миграции существующих проектов.
- Движок ВТХ детерминирован (`Decimal`), значения сверены с ГОСТ Р 50345 (IEC 60898-1).
- Проверка $I_{cn} \ge I_{кз}$ возвращает явное предупреждение при нарушении.
- Новый кейс 07 проходит `pnpm smoke:e2e` вместе с шестью прежними.
- Тесты, сборка, линтер и типы зелёные.

### 1.6 Что не является целью

Перечень приведён в § 6.

## 2. Архитектурные решения

### 2.1 Иерархия щитов в графе

В `ProjectGraphSchema` (`schemaVersion: 2`) добавляются необязательные поля:
`parentPanelId` у узла-щита, `panelRole`
(`main_vru | sub_shr | lighting_sho`), `breakingCapacityKa` в `specs`.
Новый тип ребра `feeder_line` описывает магистраль между щитами.
Суммарная потеря напряжения calc-engine считает по цепочке:

    ΔU_сумм = ΔU_маг + ΔU_групп ≤ 5%

где $\Delta U_{маг}$ — потеря на магистрали `feeder_line`,
а $\Delta U_{групп}$ — максимальная потеря на групповой линии downstream-щита.

### 2.2 Детерминированный движок ВТХ

Модель в `apps/calc-engine/app/tcc.py` (RULES § 5.1):

- тепловая зона: $1{,}13 I_n$ — не срабатывает за 1 ч; $1{,}45 I_n$ —
  срабатывает за 1 ч; $2{,}55 I_n$ — 1…60 с (для $I_n \le 32$ А);
- электромагнитная зона: B — 3–5 $I_n$, C — 5–10 $I_n$, D — 10–20 $I_n$;
  гарантированное срабатывание — по верхней границе;
- кусочно-аналитическая аппроксимация времени срабатывания, монотонная
  и непрерывная на стыках зон;
- предельная селективность $I_s$: наибольший ток, при котором
  $t_{down}(I) + \Delta t \le t_{up}(I)$ для всех $I \le I_s$, $\Delta t = 0{,}1$ с;
- проверка отключающей способности $I_{cn} \ge I_{кз}$ в точке установки.

Все вычисления в `Decimal`, результат — Zod/Pydantic-контракт с путями
$\Delta U$, $I_s$, $I_{cn}$ и списком нарушений.

### 2.3 Селектор активного щита в UI

Активный щит — свойство сессии интерфейса, а не часть графа. Переключатель
меняет контекст для 2D-компоновки, 3D-сцены и однолинейной схемы; все три
проекции читают один `ProjectGraph` (RULES § 5.2). Граф и файл `.vwc` не
изменяются при переключении.

### 2.4 Альтернативы и почему отвергнуты

| Вариант | Почему отвергнут |
|---|---|
| Хранить отдельный `.vwc` на каждый щит | Нарушение Graph-First, расхождение проекций |
| Считать ВТХ в LLM | Запрещено RULES § 5.1, невоспроизводимо |
| Ограничиваться правилом `1,6 · I_n` | Не учитывает время срабатывания и кривые |
| Делать селективность ручной таблицей в UI | Нет проверки по фактическому току КЗ |

## 3. Технические срезы

### 3.1 Срез A — расширение `ProjectGraphSchema`

Изменения в `packages/shared/src/graph.schema.ts` (без повышения версии):

    GraphNodeSchema:
      parentPanelId: Uuid | null        // для узлов kind = 'panel'
      panelRole: 'main_vru' | 'sub_shr' | 'lighting_sho' | null
      specs.breakingCapacityKa: number  // kA, опционально

    GraphEdgeSchema:
      edgeType: 'cable_line' | 'feeder_line'
      // feeder_line связывает щиты и участвует в ΔU_маг

Старые проекты читаются как однощитовые (`parentPanelId = null`,
роль `main_vru`). В `.vwc` v2 новые поля появляются только после редактирования.

### 3.2 Срез B — `POST /v1/calc/selectivity-tcc`

Вход: список аппаратов с `id`, `kind`, `ratedCurrentA`, `tripCurve`,
`breakingCapacityKa`, `parentId`, ток КЗ в точке каждого аппарата,
$\Delta U_{маг}$ и $\Delta U_{групп}$. Выход: `selectivityLimitA` ($I_s$),
`selective` (по парам), `breakingCapacityOk`, `totalVoltageDropPercent`,
`warnings`, `references` на `TCC_SELECTIVITY_V06.md`.

`PueAuditorAgent` получает инструмент `check_tcc_selectivity_tool` и включает
результат в отчёт аудита; числа приходят только из ядра (RULES § 5.1).
Тесты: граничные точки 1,13/1,45/2,55 $I_n$, зоны B/C/D, пары B32→C16,
проверка $I_{cn} < I_{кз}$.

### 3.3 Срез C — кейс 07 в золотом датасете

Добавляется `fixtures/golden-dataset/07_twostory_house_vru_shr/`:
`.vwc` с ВРУ и двумя ЩР, `expected_calc.json` с ожидаемыми $\Delta U_{сумм}$,
$I_s$ и током КЗ. `pnpm smoke:e2e` прогоняет все семь кейсов; допуски
±5 % по токам и ±0,5 п. п. по $\Delta U$ сохраняются.

### 3.4 Срез D — переключатель щитов и график ВТХ

В шапке рабочей области — селектор активного щита из дерева
`ВРУ → ЩР → ЩО`. В инспекторе аппарата защиты — интерактивный график ВТХ
(SVG/Canvas) с логарифмической осью тока, зонами B/C/D и маркерами
$I_s$ и $I_{кз}$. Переключение щита не вызывает запись в граф.

## 4. Совместимость и миграция

### 4.1 Версия графа

`schemaVersion` остаётся `2`. Все новые поля необязательны; чтение v1 и v2
без изменений. Обратная запись в v1 не требуется.

### 4.2 Файлы и API

`.vwc` и `graph_json` дополняются новыми полями без смены структуры;
Старые файлы открываются однощитовыми. DTO расчёта ВТХ — новый контракт
в `packages/shared` и Pydantic-зеркало в `calc-engine`.

### 4.3 Откат

Откат на `v0.5.0` возможен: неизвестные поля игнорируются, многощитовой
кейс 07 будет недоступен. Однощитовые проекты работают как раньше.

## 7. Риски и открытые вопросы

### 7.1 Аппроксимация ВТХ

Кусочно-аналитическая модель не заменяет паспортные кривые производителя.
Снижение риска: явная формула в протоколе, тесты на граничные точки
ГОСТ Р 50345 и предупреждение о приблизительности результата.

### 7.2 Каскад $\Delta U$

Суммирование потерь по цепочке щитов может дать значение > 5 %.
Снижение риска: указание конкретной цепочки в протоколе и подсказка
об увеличении сечения магистрали.

### 7.3 Производительность графика ВТХ

Интерактивный SVG с большим количеством точек может тормозить.
Снижение риска: логарифмическая сетка с ограниченным числом выборок
и мемоизация кривых по номиналу.

### 7.4 Открытые вопросы

| Вопрос | Статус |
|---|---|
| Порядок округления $I_s$ | Решён: 3 знака, Decimal (§ 8) |
| Выдержка $\Delta t$ для селективности | Решён: 0,1 с (§ 8) |
| Состав кейса 07 | Решён: ВРУ + два ЩР (§ 8) |
