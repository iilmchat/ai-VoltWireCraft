## 2. Архитектурные решения

### 2.1 Топология ввода в расчёте

Источник топологии — `ProjectGraph.meta.supply` (`1P 230V` или `3P 400V`)
и узел `input_source`. Значение передаётся в `PanelArchitectAgent` и в
`POST /v1/calc/auto-panel` явным полем `supplyTopology`. Ядро:

- для `1P 230V` сохраняет текущий однофазный расчёт;
- для `3P 400V` распределяет потребители по L1/L2/L3, контролирует
  перекос ≤ 15 % и подбирает 3P/4P вводные аппараты из `catalog_devices`.

Математика остаётся в `calc-engine`, LLM получает только результат (RULES § 5.1).

### 2.2 Двухступенчатый конвейер DWG

    DWG-файл (≤ 50 МБ)
        ↓ изоляция: память, таймаут 30 с, без внешних ссылок и макросов
    ODAFileConverter или dwg2dxf
        ↓ временный DXF
    ezdxf → нормализованные слои → WallSchema (координаты в метрах)

Временный DXF удаляется после разбора. Если конвертер недоступен, возвращается
явное сообщение с указанием `ODA_CONVERTER_PATH` или рекомендацией экспорта
в DXF. Все операции идут в `calc-engine`, а не в API (RULES § 5.5).

### 2.3 Разделение чанков Vite

`Panel3DView` и зависимости Three.js загружаются через `React.lazy`
только при открытии вкладки «3D-щит». Остальные проекции и копилот
остаются в основном чанке; отложенная загрузка не меняет граф и состояние редактора.

### 2.4 Альтернативы и почему отвергнуты

| Вариант | Почему отвергнут |
|---|---|
| Определять фазы по названию проекта | Недетерминированно; ошибки для 400 В |
| Разбирать DWG в браузере | Нет изоляции и контроля таймаута (RULES § 5.5) |
| Держать MinIO в базовом compose | Образ недоступен в части registry (`KI-006`) |
| Загружать Three.js сразу | Увеличивает первичный чанк и время старта Tauri |

## 3. Технические срезы

### 3.1 Срез A — трёхфазный ввод (`KI-007`)

В `packages/shared` расширяется `AutoPanelRequest`: поле `supplyTopology`
(`'1P_230V' | '3P_400V'`) и опциональный `panelPoles` (3/4). В
`apps/calc-engine/app/auto_panel.py` добавляется расчёт баланса по фазам:

    перекос = (I_max - I_min) / I_max × 100% ≤ 15%

Подбор вводного аппарата из `catalog_devices` по числу полюсов и номиналу;
для 3P/4P модели учитываются три фазы и neutral. `PanelArchitectAgent` передаёт
топологию из `ProjectGraph.meta` без вызовов расчёта внутри LLM.

### 3.2 Срез B — конвертер DWG и Docker profile `s3` (`KI-005`, `KI-006`)

| Шаг | Компонент | Что происходит |
|---|---|---|
| 1 | API | `POST /projects/:id/import-cad`, проверка расширения `.dwg` и размера |
| 2 | BullMQ | задача `convert-dwg`, лимит 50 МБ и 30 с |
| 3 | `calc-engine` | `ODAFileConverter` по `ODA_CONVERTER_PATH` или `dwg2dxf` в сандбоксе |
| 4 | `calc-engine` | `ezdxf` разбирает временный DXF в `WallSchema`, файл удаляется |
| 5 | API | стены записываются в граф после Zod-валидации |

В `docker-compose.yml` сервис MinIO переносится в profile `s3`:
`docker compose --profile s3 up -d`. Базовый запуск использует
`STORAGE_DRIVER=local`; `.env.example` дополняется комментариями.

### 3.3 Срез C — шаблоны 04–06 и золотой датасет

Добавляются три типовых объекта (итого шесть):

- `04_office_400v` — офис с трёхфазным вводом и мастер-выключателем;
- `05_cafe_230v` — кафе с мокрыми зонами и мощной кухонной линией;
- `06_workshop_dwg` — мастерская с импортом DWG.

Каждый шаблон содержит `.vwc`, подложку или `.dxf`/`.dwg` и
`expected_calc.json`. `pnpm smoke:e2e` проходит по всем шести кейсам
и сравнивает показатели с допусками из `fixtures/golden-dataset/README.md`.

### 3.4 Срез D — lazy-загрузка и галерея шаблонов

`Panel3DView` оборачивается в `React.lazy`, Three.js выносится в отдельный
чанк; показывается skeleton на время загрузки. Галерея шаблонов получает
шесть карточек с превью и кнопкой «Загрузить пример». Состояние редактора
не сбрасывается при переключении вкладок.

## 4. Совместимость и миграция

### 4.1 Версия графа

`schemaVersion` остаётся `2`. Новые поля (`supplyTopology`, `panelPoles`)
необязательны; старые проекты читаются без миграции и трактуются как
`1P 230V`. Запись добавляет поле при первом сохранении через автосборку.

### 4.2 Файлы и БД

`.vwc` v2 остаётся читаемым; `graph_json` в PostgreSQL не меняет структуру.
Docker profile `s3` не влияет на схему БД и переменные расчётного ядра.

### 4.3 Откат

Откат на `v0.4.0` возможен: новые поля игнорируются старой схемой,
DWG-импорт и шаблоны 04–06 недоступны, базовый запуск работает как раньше.

## 7. Риски и открытые вопросы

### 7.1 Конвертер DWG

ODA File Converter требует лицензии, `dwg2dxf` может не поддерживать
новые версии формата. Снижение риска: два варианта конвертера, таймаут 30 с,
валидация результата Zod и явная диагностика при отсутствии инструмента.

### 7.2 Трёхфазный баланс

Жадная балансировка может дать перекос > 15 % при нескольких мощных потребителях.
Снижение риска: тесты на граничные случаи, предупреждение вместо «тихой»
подгонки, ручное перераспределение через инспектор.

### 7.3 Разделение чанков

Lazy-загрузка может вызвать мерцание 3D-вкладки. Снижение риска: skeleton,
предзагрузка при наведении на вкладку, smoke-проверка переключения.

### 7.4 Открытые вопросы

| Вопрос | Кому | Статус |
|---|---|---|
| Основной конвертер DWG: ODA или `dwg2dxf` | Архитектор | Открыт |
| Политики ручного перераспределения фаз при перекосе > 15 % | Владелец продукта | Открыт |
| Состав трёх новых шаблонов 04–06 | Владелец продукта | Открыт |
