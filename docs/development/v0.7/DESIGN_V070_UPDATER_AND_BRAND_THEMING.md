## 1. Контекст

### 1.1 Точка старта

**Релиз:** `v0.6.0` опубликован; 268 тестов и 379 smoke-проверок зелёные.
Реализованы многощитовые иерархии, ВТХ-селективность и седьмой эталон.
**Продукт:** САПР электрических сетей 0,4 кВ и сборки щитов НКУ для ИЖС,
квартир и коммерческой недвижимости.
**Стек:** NestJS 12, React 19 + Vite + Konva.js + Tauri 2 + Three.js,
Python/FastAPI, PostgreSQL 17 + pgvector.
**Документы:** RULES v1.0.0, `DESIGN_V060`, `PUE_RULES_V02.md`,
`PUE_SHORT_CIRCUIT_V03.md`, `TCC_SELECTIVITY_V06.md`.

### 1.2 Проблема

Десктопное приложение распространяется неподписанными артефактами без
автообновления: пользователь вручную скачивает новую версию с GitHub Releases.
Одновременно визуальный стиль VoltWireCraft не соответствует брендбуку
экосистемы IIRuChating: отсутствуют единые токены Material 3, фирменные
шрифты и логотипы, а светлая и тёмная темы реализованы неполно — холсты
Konva.js/Three.js и график ВТХ не перекрашиваются при смене темы.

### 1.3 Новые возможности

| Возможность | Обозначение | Что делает |
|---|---|---|
| Автообновление | `tauri-plugin-updater` | Тихая проверка при старте, подписанный манифест `latest.json`, прогресс и перезапуск |
| Подпись артефактов | `TAURI_SIGNING_PRIVATE_KEY` | Криптографическая подпись `.msi/.exe` и `.AppImage` в GitHub Actions |
| Брендбук | `ai-brand v1.1` | Фирменные логотипы, фавикон, шрифты Inter/Manrope |
| Система тем | `data-theme` | Светлая, тёмная и системная темы на базе `--md-sys-color-*` |
| Адаптация холстов | Konva/Three/TCC | Цвета слоёв, сетки и графиков следуют активной теме |

### 1.4 Продуктовые сценарии

1. При запуске десктоп тихо проверяет GitHub Releases; при наличии новой
   версии показывает баннер с прогрессом скачивания и кнопкой перезапуска.
2. Пользователь работает офлайн — проверка обновлений завершается по таймауту
   без блокировки интерфейса, все локальные функции доступны (RULES § 5.4).
3. Пользователь выбирает «Системная» тема — приложение следует настройкам ОС;
   переключение сохраняется в `localStorage`.
4. При смене темы перекрашиваются не только панели, но и план, 3D-щит и
   график ВТХ.

### 1.5 Цели и критерии успеха

- Обновление доставляется только из подписанного манифеста `latest.json`;
  при отсутствии сети приложение работает как раньше.
- Все темы используют токены `--md-sys-color-*` из `theme-m3.css` и не
  содержат «жёстко заданных» цветов в компонентах.
- Шрифты и логотипы поставляются локально, без обращения к CDN.
- Тесты, сборка, линтер и типы зелёные; smoke по трём темам проходит.

### 1.6 Что не является целью

Перечень приведён в § 6.

## 2. Архитектурные решения

### 2.1 Механизм автообновления

`tauri-plugin-updater` проверяет `latest.json` из GitHub Releases
(`https://github.com/iilmchat/ai-VoltWireCraft/releases/latest/download/latest.json`).
Манифест содержит версию, URL артефактов и подписи. Приватный ключ
`TAURI_SIGNING_PRIVATE_KEY` хранится в GitHub Secrets, публичный — в конфиге
`tauri.conf.json` (`updater.pubkey`). Обновление:
тихая проверка при старте → уведомление → скачивание с прогрессом →
проверка подписи → перезапуск. Ошибка сети не блокирует интерфейс.

### 2.2 Система тем на базе Material 3

`theme-m3.css` из `iilmchat/ai-brand` v1.1 определяет токены
`--md-sys-color-*` для светлой и тёмной схем. Корневой элемент получает
`data-theme="light" | "dark"`, системный режим определяется через
`prefers-color-scheme` и не записывает фиксированное значение. Tailwind CSS 4
получает токены через `@theme` и использует `var(--md-sys-color-*)`.
Цвета холстов Konva.js, сцены Three.js и SVG-графика ВТХ читаются из того же
набора токенов через `getComputedStyle` и обновляются по событию смены темы.

### 2.3 Альтернативы и почему отвергнуты

| Вариант | Почему отвергнут |
|---|---|
| Обновление через собственный HTTP-эндпоинт | Дополнительная инфраструктура и нет подписи GitHub Releases |
| Хранить приватный ключ в репозитории | Нарушение RULES § 2.6 |
| Хардкод цветов в компонентах | Расхождение между панелями и холстами при смене темы |
| Загружать шрифты с CDN | Не работает в офлайн-режиме Tauri (RULES § 5.4) |

## 3. Технические срезы

### 3.1 Срез A — updater и подписанные релизы

В `apps/web/src-tauri/Cargo.toml` добавляется `tauri-plugin-updater`,
в `src/main.rs` — регистрация плагина. В `.github/workflows/release-desktop.yml`
на шаге сборки задаются `TAURI_SIGNING_PRIVATE_KEY` и
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` из GitHub Secrets; после сборки
публикуются `.msi/.exe`, `.AppImage`, их `.sig` и `latest.json`.
Проверка подписи выполняется плагином до установки.

### 3.2 Срез B — ассеты брендбука и переключатель тем

Из `iilmchat/ai-brand` v1.1 импортируются:

- `public/brand/theme-m3.css` — токены `--md-sys-color-*`;
- `public/brand/favicon.svg`, `public/brand/logo-icon.svg`;
- локальные файлы шрифтов `Inter` и `Manrope` (`public/brand/fonts/`).

В `apps/web/src/i18n/{ru,en}.json` добавляются строки переключателя.
Компонент `ThemeSwitcher` пишет выбор в `localStorage` и выставляет
`data-theme` на `<html>`; системный режим слушает `matchMedia`. Холсты
подписываются на смену темы и пересчитывают палитру.

### 3.3 Срез C — контроллер обновлений и баннер

`apps/web/src/lib/updater.ts` инкапсулирует вызовы плагина:
`checkForUpdates`, `download`, `install`, состояние
`idle | checking | available | downloading | ready | error` и таймаут
проверки при офлайн-режиме. `UpdateBanner.tsx` в `Header.tsx` показывает
версию, прогресс скачивания и кнопки «Установить и перезапустить» /
«Позже». Ошибка сети отображается ненавязчиво и не блокирует работу.

## 4. Совместимость и миграция

### 4.1 Граф и форматы

`ProjectGraphSchema` и `schemaVersion: 2` не меняются; `.vwc` и `graph_json`
остаются совместимыми. Тема и состояние обновления — свойства сессии,
не попадают в файл проекта.

### 4.2 Веб-версия

В браузере плагин updater не используется: проверка обновлений доступна
только в Tauri. Веб получает темы и брендинг без изменений контрактов API.

### 4.3 Откат

Откат на `v0.6.0` возможен для файлов проекта; артефакт `v0.7.0` можно
заменить предыдущим вручную. Настройки темы в `localStorage` игнорируются
старой версией.

## 6. Что НЕ входит в v0.7.0

- автообновление веб-клиента;
- принудительное обновление без согласия пользователя;
- генерация ключей подписи внутри приложения;
- новые форматы РД и расчётных отчётов;

## 7. Риски и открытые вопросы

### 7.1 Отсутствие сети

В офлайн-режиме Tauri проверка обновлений может «зависнуть». Снижение риска:
таймаут, фоновый запуск, кэширование последнего результата и явный
индикатор офлайна (RULES § 5.4).

### 7.2 Локальные шрифты

Шрифты должны поставляться в составе приложения. Снижение риска: файлы
`public/brand/fonts/` в репозитории, `@font-face` без внешних URL,
тест на отсутствие сетевых запросов при первом рендере.

### 7.3 Утечка ключа подписи

Приватный ключ хранится только в GitHub Secrets. Снижение риска:
запрет коммитов с паттернами ключей (lint-staged), ротация при подозрении.

### 7.4 Открытые вопросы

| Вопрос | Статус |
|---|---|
| Периодичность фоновой проверки обновлений | Решён: при старте и раз в 24 ч (§ 8) |
| Источник токенов тем | Решён: `theme-m3.css` из `ai-brand` v1.1 (§ 8) |
| Политика шрифтов | Решён: только локальные файлы (§ 8) |
