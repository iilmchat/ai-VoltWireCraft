### 1.4 Продуктовые сценарии

1. **ИЖС:** загрузить план дома → расставить розетки, выключатели и щит →
   провести кабельные линии → сохранить проект в `.vwc`.
2. **Квартира:** загрузить PDF-план застройщика → откалибровать масштаб →
   уточнить стены → расставить ЭУИ →
   передать граф в расчётное ядро на следующем релизе.
3. **Коммерция:** загрузить PDF-план → разметить помещения → подготовить основу
   для будущей автосборки НКУ и однолинейной схемы.

### 1.5 Цели и критерии успеха

- Граф проекта валидируется Zod и является единственным источником данных для
  холста; расхождение между графом и отображением отсутствует.
- Подложка PDF/PNG/JPG загружается и рендерится на клиенте; лимит файла — 25 МБ,
  таймаут обработки — 30 с.
- ЭУИ расставляются мышью, привязываются к стенам и сохраняются в графе с
  координатами в метрах.
- Проект открывается и сохраняется в Tauri без сети (RULES § 5.4).
- Сборка без ошибок и предупреждений, тесты зелёные, документация обновлена в
  том же коммите (RULES § 2.1, § 3.8).

### 1.6 Что не является целью

Список приведён в § 6 (основное: расчёты, однолинейная схема, ИИ-аудит).

## 2. Ключевое архитектурное решение

### 2.1 Граф как единственный источник истины

Вся структура проекта хранится в `ProjectGraphSchema` — типизированном JSON.
API отдаёт граф целиком; клиент (Konva.js) строит визуальные слои из графа и
пишет правки обратно в граф. Никакие координаты или связи не живут только
в состоянии интерфейса (RULES § 5.2).

**Почему не «файл чертежа как источник»:** форматы PDF/DXF/DWG предназначены для
обмена, а не для редактирования модели; их представление с потерей данных нельзя
использовать как каноническое хранилище.

### 2.2 Две проекции одного графа

- **План этажа** — проекция в Konva.js (реализуется в v0.1).
- **Однолинейная схема** — вторая проекция того же графа; в v0.1 резервируются
  типы узлов и УГО, но генерация схемы не реализуется (§ 6).

Такое разделение гарантирует: правка ЭУИ на плане автоматически доступна схеме
без синхронизации двух документов.

### 2.3 Подложки: рендер на клиенте, калибровка масштаба

В `v0.1.0` поддерживаются PDF, PNG и JPG. PDF рендерится в выбранную страницу
через `pdfjs-dist`, растровые изображения загружаются напрямую; подложка
отображается на холсте Konva.js. Пользователь вручную задаёт коэффициент
`scaleMetersPerPx`, после чего все точки переводятся в метры (СИ, RULES § 5.3).
Лимит файла — 25 МБ, таймаут обработки — 30 с.

Векторный разбор DXF/DWG перенесён в `v0.2.0`. Когда он будет реализован,
разбор выполняется в изолированном окружении с ограничениями по памяти и
времени, без исполнения внешних ссылок и макросов (RULES § 5.5).

### 2.4 Единицы измерения

Все длины — в метрах (`m`), площади сечений — в квадратных миллиметрах
(`mm2`), мощности — `W`, напряжения — `V`, токи — `A`. Перевод в другие единицы
(например, в см или кВт) делается только при отображении (RULES § 5.3).

### 2.5 Граница между ИИ и математикой

В v0.1 расчётов нет, но контракт инструмента расчётного ядра закладывается
сразу: `calc-engine` принимает граф и возвращает структурированный результат.
ИИ-агент в более поздних релизах сможет только вызывать этот инструмент и
комментировать результат; вычисление сечений, токов КЗ и номиналов УЗО/АВДТ
внутри модели запрещено (RULES § 5.1).

### 2.6 Файл проекта `.vwc`

`.vwc` — JSON-обёртка над графом:

```json
{
    "format": "vwc-project",
    "schemaVersion": 1,
    "graph": { "...": "ProjectGraphSchema" },
    "savedAt": "2026-11-19T00:00:00Z"
}
```

Открытие файла начинается с проверки `format` и `schemaVersion` Zod; при
несовпадении версии предлагается миграция или отказ от загрузки (§ 4.2).

### 2.7 Альтернативы и почему отвергнуты

| Вариант | Почему отвергнут |
|---|---|
| Хранить план как SVG и редактировать его напрямую | SVG — не модель; нет связей и типов ЭУИ |
| Разбирать DXF/DWG в браузере на старте | Требует изоляции по памяти и таймауту; перенесено в `v0.2.0` (RULES § 5.5) |
| Две независимые модели: план и схема | Рассинхронизация; нарушение Graph-First (RULES § 5.2) |
| Хранить единицы в именах полей | Усложняет миграции; нарушение RULES § 5.3 |

## 3. Технические срезы

### 3.1 Срез A — `ProjectGraphSchema`

Каноническая схема зафиксирована в `packages/shared` и используется API,
клиентом и файлом `.vwc`. Граф — единый источник истины для плана и схемы
(RULES § 5.2); все физические величины — в базовых единицах СИ (RULES § 5.3).
Колонка `jsonb` в PostgreSQL типизируется через `$type<ProjectGraph>()`.

```ts
import { z } from 'zod';

/** Базовый набор УГО узлов графа: 11 типов, утверждён в § 8. */
export const NodeKindSchema = z.enum([
    'input_source',    // Ввод
    'panel',           // Щит НКУ
    'circuit_breaker', // Автоматический выключатель
    'rcd',             // УЗО
    'rcbo',            // АВДТ / дифференциальный автомат
    'relay_voltage',   // Реле напряжения
    'contactor',       // Контактор
    'socket',          // Розетка
    'light_fixture',   // Светильник
    'switch',          // Выключатель
    'appliance',       // Стационарный потребитель
]);

/** Точка на плане; координаты в метрах (СИ). */
export const PointSchema = z.object({
    x: z.number().finite(),
    y: z.number().finite(),
});

/** Подложка: PDF (отрендеренная страница) или растр PNG/JPG. */
export const BackgroundSchema = z.object({
    kind: z.enum(['pdf', 'png', 'jpg']),
    name: z.string().min(1),
    pageNumber: z.number().int().positive().nullable(),
    widthPx: z.number().positive(),
    heightPx: z.number().positive(),
    dataUrl: z.string().min(1),
});

/** Параметры плана этажа. */
export const FloorPlanSchema = z.object({
    background: BackgroundSchema.nullable(),
    scaleMetersPerPx: z.number().positive().nullable(), // m/px; null — не откалиброван
    ceilingHeightM: z.number().positive(),              // m
});

/** Тип зоны помещения. */
export const RoomZoneTypeSchema = z.enum([
    'living', 'wet', 'kitchen', 'outdoor', 'utility',
]);

/** Зона помещения: вершины многоугольника в метрах (СИ). */
export const RoomZoneSchema = z.object({
    id: z.string().uuid(),
    name: z.string().min(1),
    type: RoomZoneTypeSchema,
    polygon: z.array(PointSchema).min(3),
});

/** Стена, перегородка или проём; координаты в метрах (СИ). */
export const WallSchema = z.object({
    id: z.string().uuid(),
    kind: z.enum(['wall', 'partition', 'doorway', 'window']),
    path: z.array(PointSchema).min(2),
    thickness: z.number().nonnegative(), // m
});

/** Узел графа: УГО, положение на плане, место в щите и спецификация. */
export const GraphNodeSchema = z.object({
    id: z.string().uuid(),
    kind: NodeKindSchema,
    label: z.string().min(1),
    planPosition: PointSchema.nullable(),              // m; null — узел только на схеме
    panelSlot: z.number().int().positive().nullable(), // место в щите НКУ
    specs: z.object({
        ratedPower: z.number().nonnegative(),     // W
        ratedCurrent: z.number().positive(),      // A
        crossSection: z.number().positive(),      // mm2
        mountingHeight: z.number().nonnegative(), // m
    }),
});

/** Ребро графа: кабельная линия между узлами. */
export const GraphEdgeSchema = z.object({
    id: z.string().uuid(),
    from: z.string().uuid(),
    to: z.string().uuid(),
    cableSpecs: z.object({
        crossSection: z.number().positive(),        // mm2
        conductorCount: z.number().int().positive(),
        material: z.enum(['cu', 'al']),
        length: z.number().nonnegative(),           // m
    }),
});

export const ProjectGraphSchema = z.object({
    schemaVersion: z.literal(1),
    id: z.string().uuid(),
    name: z.string().min(1),
    floorPlan: FloorPlanSchema,
    rooms: z.array(RoomZoneSchema),
    walls: z.array(WallSchema),
    nodes: z.array(GraphNodeSchema),
    edges: z.array(GraphEdgeSchema),
});

export type ProjectGraph = z.infer<typeof ProjectGraphSchema>;
```

### 3.2 Срез B — загрузка подложек

В `v0.1.0` подложка обрабатывается **на клиенте**: серверный разбор DXF/DWG
не используется и перенесён в `v0.2.0`.

| Шаг | Компонент | Что происходит |
|---|---|---|
| 1 | Клиент | выбор файла PDF/PNG/JPG; проверка размера — не более 25 МБ |
| 2 | `pdfjs-dist` | рендер выбранной страницы PDF в растр (для PNG/JPG — прямая загрузка) |
| 3 | Konva.js | отображение подложки; таймаут обработки — 30 с |
| 4 | Клиент | ручная калибровка масштаба: пользователь задаёт `scaleMetersPerPx` |
| 5 | `packages/shared` | подложка и коэффициент сохраняются в `floorPlan` графа (`FloorPlanSchema`) |

Все точки подложки переводятся в метры через `scaleMetersPerPx`; физические
длины и высоты (в том числе `ceilingHeightM`) хранятся в СИ (RULES § 5.3).
Ошибки загрузки и рендера показываются пользователю без стека исключения.

### 3.3 Срез C — 2D-редактор на Konva.js

Слои холста (от нижнего к верхнему): подложка → стены и проёмы → кабельные
трассы → ЭУИ → слой выделения и направляющих.

Действия:

- перетаскивание ЭУИ из палитры на план;
- привязка к ближайшей стене с точностью по умолчанию 0,2 m;
- трассировка кабеля по точкам с привязкой к узлам графа;
- отмена/повтор действий через историю правок графа;
- горячие клавиши и сохранение по `Ctrl+S`.

### 3.4 Срез D — сохранение в PostgreSQL и файл `.vwc`

- `projects` — метаданные проекта; граф хранится в колонке `graph jsonb`.
- `GET /projects/:id` / `PATCH /projects/:id/graph` — чтение и запись графа с
  Zod-валидацией на границе.
- `.vwc` формируется сериализацией `{ format, schemaVersion, graph, savedAt }`
  и проверяется схемой `VwcFileSchema` из `packages/shared`.
- Веб: скачивание файла; настольное приложение: системный диалог Tauri (§ 3.5).

### 3.5 Срез E — офлайн-режим Tauri

- Команды `save_project` и `open_project` работают с локальным путём, выбранным
  пользователем; доступ к сети не требуется (RULES § 5.4).
- Общая кодовая база: бизнес-логика редактирования графа не зависит от платформы;
  различаются только адаптеры хранения.
- Если функция требует сервера (например, разбор подложки), в офлайне показывается
  явное сообщение; редактирование графа остаётся доступным.

## 4. Совместимость и миграция

### 4.1 Первый релиз

Совместимость с предыдущими версиями отсутствует: v0.1 — первый релиз. Это
позволяет зафиксировать канонический формат без миграций.

### 4.2 Версия схемы

Поле `schemaVersion` обязательно. При открытии `.vwc` или чтении `jsonb`:

- `schemaVersion = 1` — загрузка;
- большее значение — отказ с сообщением о необходимом обновлении приложения;
- меньшее — применение цепочки миграций, если она реализована, иначе отказ.

### 4.3 База данных

Миграции применяются до старта приложения. Граф хранится целиком в `jsonb`, что
упрощает атомарную запись; индексы добавляются только под реальные запросы.

### 4.4 API-контракты

Все ответы и тела запросов валидируются Zod; клиентские типы выводятся из тех же
схем. Изменение контракта требует правки `CHANGELOG.md` в том же коммите.

### 4.5 Откат

Откат релиза возможен без изменения данных: формат v1 остаётся читаемым. При
несовместимом изменении схемы вводится `schemaVersion = 2` и миграция.

## 6. Что НЕ входит в v0.1

- расчёты сечений кабелей, токов короткого замыкания и номиналов УЗО/АВДТ
  (только через вызов инструментов расчётного ядра, RULES § 5.1);
- автосборка щита НКУ/ВРУ и генерация однолинейной схемы (заложена модель УГО,
  генерация — следующий релиз);
- ИИ-консультант и аудит проекта по ПУЭ-7;
- векторный поиск по нормативной базе (pgvector используется инфраструктурно);
- разбор DXF/DWG и распознавание размеров по векторным слоям — перенесён в `v0.2.0`;
  в `v0.1.0` доступны подложки PDF, PNG, JPG (до 25 МБ, таймаут 30 с) с ручной
  калибровкой масштаба;
- совместная работа нескольких пользователей, облачная синхронизация;
- 3D-визуализация и экспорт в форматы чертежей систем проектирования.

## 7. Риски и открытые вопросы

### 7.1 Качество разбора подложек

Разные производители чертежей по-разному кодируют стены и проёмы. Результат
разбора может требовать ручной доводки. Снижение риска: нормализованные слои и
режим «только подложка», когда пользователь сам обводит стены.

### 7.2 Производительность холста

Большие планы с тысячами примитивов могут тормозить. Снижение риска: виртуализация
слоёв и ограничение детализации подложки масштабом просмотра.

### 7.3 Изоляция разбора

Ограничения по памяти и таймауту должны быть проверены на враждебных файлах
(большие вложенные структуры, внешние ссылки). Снижение риска: отдельный процесс
расчётного ядра с квотами и тестами на отказ.

### 7.4 Открытые вопросы

| Вопрос | Кому | Статус |
|---|---|---|
| Выбрать ORM для PostgreSQL (Drizzle или Prisma) | Архитектор | Решён: Drizzle ORM (§ 8) |
| Формат координат подложки: привязка к целочисленной сетке или произвольные метры | Архитектор | Решён: пиксели + `scaleMetersPerPx`, длины в метрах (§ 8) |
| Какие УГО считать базовыми для будущей однолинейной схемы | Владелец продукта | Решён: 11 типов УГО (§ 8) |
| Предельный размер загружаемого файла и таймаут обработки | Владелец продукта | Решён: 25 МБ и 30 с (§ 8) |
