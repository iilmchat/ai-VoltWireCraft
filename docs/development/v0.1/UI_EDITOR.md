# UI v0.1 — редактор плана VoltWireCraft

**Файл:** `docs/development/v0.1/UI_EDITOR.md`
**Дата:** 2026-11-19
**Статус:** Draft
**Стек:** React 19 · Vite · Konva.js (`react-konva`) · Zustand · Tailwind CSS 4

---

## 1. Назначение

Документ описывает интерфейс веб-клиента релиза 0.1: загрузку подложки,
калибровку масштаба, зонирование, расстановку ЭУИ, трассировку кабелей,
локальное сохранение `.vwc` и работу с API проектов.

Единственный источник истины — каноническая `ProjectGraphSchema` из
`@voltwirecraft/shared/graph.schema` (RULES § 5.2). Граф содержит:
`floorPlan` (подложка, `scaleMetersPerPx`, `ceilingHeightM`), `rooms`,
`walls`, `nodes` (УГО, положение `planPosition`, `specs`) и `edges`
(`cableSpecs`, дополнительно `waypointsPx`, `edgeType`, `cableBrand`).
Координаты плана, зон и узлов хранятся в метрах; точки трассы — в пикселях
подложки (`waypointsPx`) и переводятся в метры через масштаб.

## 3. Холст

### 3.1 Навигация

| Действие | Управление |
|---|---|
| Зум к курсору | Колесико; `exp(-deltaY · 0,001)`, пределы 0,05–20 |
| Панорамирование | Средняя кнопка мыши или `Space` + левая кнопка + drag |
| Вписать подложку | Кнопка «Сброс вида» |
| Удалить выделенное | `Delete` / `Backspace` |
| Отменить жест | `Escape` (контур, отрезок, трасса) |

Экранная точка переводится в пиксели подложки формулой
`(pointer - viewport) / viewport.scale`, затем в метры через `scaleMetersPerPx`.

### 3.2 Подложка

- PNG/JPG: data URL + `Image.decode()`.
- PDF: `pdfjs-dist` рендерит выбранную страницу в canvas с масштабом 2,
  результат сохраняется как PNG data URL; worker подключается через Vite `?url`.
- Подложка — нижний `Konva.Layer`, не редактируется напрямую.
- Data URL в `Background` делает `.vwc` самодостаточным для офлайн-режима (RULES § 5.4).

## 4. Инструменты

### 4.1 Калибровка (`ScaleCalibratorTool`)

Отрезок поверх известного размера → ввод длины в мм → запись
`floorPlan.scaleMetersPerPx = (мм / 1000) / длина_пикселей`.
До калибровки действует резервный масштаб 1 пикс = 1 мм.

### 4.2 Зонирование (`RoomZoneTool`)

Типы: `living`, `wet`, `kitchen`, `outdoor`, `utility`. Контур замыкается
двойным кликом, `Enter`, кликом по первой вершине или кнопкой «Применить».
Полигон сохраняется в метрах, заливается полупрозрачно, подпись — в центроиде.

### 4.3 Расстановка ЭУИ (`DevicePlacementTool`)

Палитра: `panel` (щит), `socket`, `switch`, `light_fixture`, `appliance`.
Установка кликом по «вооружённому» типу или drag-and-drop
(MIME `application/x-vwc-device`). Канонические kinds УГО —
`panel`, `socket`, `switch`, `light_fixture`, `appliance` и др. (11 типов).

Инспектор редактирует УГО/подпись (`label`), мощность (`specs.ratedPower`, Вт),
высоту установки (`specs.mountingHeight`, м) и привязку к зоне (`roomId`).

### 4.4 Трассировка кабеля (`CableRouteTool`)

1. Выбрать инструмент «Трассировка кабеля».
2. Кликнуть по узлу-источнику (щит, ввод, УЗО/АВДТ).
3. Поставить поворотные точки (`waypointsPx`) кликами по холсту.
4. Кликнуть по узлу-приёмнику (розетка, выключатель, светильник, прибор).
5. Создаётся `GraphEdge`: `from`, `to`, `cableSpecs` (сечение, число жил,
   материал, длина), `waypointsPx`, `edgeType: 'cable_line'`,
   `cableBrand: 'ВВГнг(А)-LS'`. По умолчанию сечение 1,5 мм², 3 жилы, медь.

Инспектор линии позволяет изменить марку, сечение и число жил.

## 5. Сохранение

### 5.1 Офлайн `.vwc`

```json
    {
        "format": "vwc-project",
        "schemaVersion": 1,
        "graph": { "...": "ProjectGraphSchema" },
        "savedAt": "2026-11-19T00:00:00Z"
    }
```

Экспорт/импорт проверяются через `VwcFileSchema`; ошибки импорта
диагностируются по кодам (`invalidJson`, `invalidFormat`, `newerVersion`,
`olderVersion`, `invalidGraph`).

### 5.2 Серверное хранение

`apps/web/src/lib/apiClient.ts` — типизированный клиент с Zod-валидацией ответов:

| Кнопка | Запрос |
|---|---|
| «Сохранить на сервер» | `POST /projects` (если проекта ещё нет) → `PUT /projects/:id/graph` |
| «Загрузить с сервера» | `GET /projects/:id` (идентификатор вводится в диалоге) |

Базовый URL: `VITE_API_URL` или `http://localhost:3000`. Ошибки API показываются
в строке статуса; офлайн-кнопки `.vwc` остаются доступными всегда (RULES § 5.4).
Дополнительно доступна загрузка подложки на сервер:
`POST /projects/:id/floor-plans` (multipart `file`).

## 6. Проекции и ИИ-инженер (v0.2.0)

### 6.1 Вкладки

Рабочая область имеет пять вкладок: «План помещений», «Компоновка щита (НКУ)»,
«3D-щит (НКУ)», «Однолинейная схема», «Спецификация». Все они читают один и тот же
`ProjectGraph` из `editorStore` (RULES § 5.2); переключение не изменяет граф.
С v0.5.0 вкладка «3D-щит (НКУ)» загружается через `React.lazy` отдельным чанком.

### 6.2 Компоновка щита (`PanelLayoutEditor`)

SVG-представление корпуса щита с DIN-рейками по 18 модулей в ряд. Ширина модуля —
18 мм (`DIN_MODULE_WIDTH_MM`); типы УГО занимают 1–4 модуля
(`MODULES_PER_KIND`). Модули размещаются по `panelSlot` узла, сортируются по
номеру слота и переносятся на следующую рейку при переполнении. Подписи:
маркировка (`label`, например `QF1`), номинал (`ratingLabel`: `C16`,
`25А 30мА`), ширина (`1М`…`4М`), слот и фаза. Фаза вычисляется по слоту
(1 → L1 жёлтый, 2 → L2 зелёный, 0 → L3 красный). Клик по модулю выделяет узел
в графе; `InspectorPanel` позволяет изменить УГО и номинал (`specs.ratedCurrent`),
после чего щит и схема перерисовываются из графа.

### 6.3 Однолинейная схема (`SingleLineDiagramView`)

Автоматическая древовидная раскладка по ГОСТ: ввод → вводной автомат → реле
напряжения → групповые УЗО/АВДТ → отходящие линии. Связи берутся из `edges`,
при отсутствии связи узел крепится к ближайшему узлу старшего уровня. У каждой
линии подписываются марка кабеля, сечение (мм²), длина (м), мощность (кВт) и ток
(А). Клик по узлу/линии выделяет соответствующий элемент графа. Кнопки экспорта:
SVG (сериализация DOM), PNG (canvas), PDF (jsPDF, A4 landscape).

### 6.4 Спецификация (`BillOfMaterialsTable`)

Кабели группируются по марке, сечению, числу жил и материалу; считается суммарная
длина (`cableSpecs.length`, при нулях — оценка по `waypointsPx` и масштабу).
Аппараты защиты и щит перечисляются по узлам с `panelSlot`, с артикулами и ценами
из локального справочника. Итоговая строка показывает сумму. Экспорт — CSV
(UTF-8 BOM, `;`) и XLSX (SheetJS).

### 6.5 ИИ-Инженер (`AiAssistantDrawer`)

Правая выдвижная панель открывается кнопкой в шапке. Две кнопки:

| Кнопка | Запрос | Действие |
|---|---|---|
| «Собрать щит с ИИ» | `POST /projects/:id/ai/assemble-panel` | заменяет граф ответом агента, открывает вкладку щита |
| «Аудит по ПУЭ-7» | `POST /projects/:id/ai/audit-pue` | показывает список замечаний с цитатами нормативов |

Клик по замечанию выделяет проблемный узел/линию и открывает схему или
спецификацию. Все числа в ответе агента проверяются Zod-схемами; физические
расчёты выполняет детерминированное ядро, а не модель (RULES § 5.1).

## 7. Релиз v0.3.0: CAD, схема v2, КЗ и Tauri

### 7.1 Схема v2 и миграция

Клиент работает с канонической `ProjectGraphSchema` (`schemaVersion: 2`).
Файлы v1 и данные с сервера проходят через `parseVwcFile` /
`migrateProjectGraphV1ToV2`: для каждой линии вычисляются `waypointsM`
(метры, СИ), узлам щита назначаются `panelSlot`. Экспорт `.vwc` всегда
записывает версию 2. KI-003 закрыт.

### 7.2 Импорт DXF/DWG и стены

Кнопка «Импорт DXF/DWG» в шапке отправляет файл на
`POST /projects/:id/import-cad`; полученные стены (`graph.walls`, координаты
в метрах) добавляются в граф и рисуются отдельным векторным слоем Konva
(жёлтые/зелёные проёмы, серые стены, пунктирные перегородки). Input принимает
оба расширения — `.dxf` и `.dwg`; во время разбора показывается индикатор
прогресса. Если на сервере нет конвертера DWG, API возвращает явное сообщение,
которое отображается в панели уведомлений шапки вместе с подсказкой экспортировать
чертёж в DXF (RULES § 5.4). При расстановке и перемещении ЭУИ включено магнитное
прилипание к стенам в радиусе 0,2 м («snap»), что ускоряет привязку розеток
и выключателей.

### 7.3 Живой каталог и смета (KI-004)

Спецификация загружает `GET /catalog/devices` на монтировании, кэширует
результат в `uiStore` на 5 минут и показывает «Цены из API-каталога». Кнопка
«Обновить прайс» принудительно обновляет кэш. Реальные артикулы и цены
попадают в таблицу и в экспорт CSV/XLSX. Если API недоступен (офлайн-Tauri),
используется встроенный справочник с индикатором «Локальный справочник».

### 7.4 Расчёт КЗ и селективность

Кнопка «Расчёт КЗ» вызывает `POST /projects/:id/short-circuit`. В инспекторе
(узел-автомат или линия) и в подписях линий однолинейной схемы показываются
$I_{кз}^{(1)}$ (А), потеря напряжения ΔU (%) и бейдж селективности:
зелёный — норма, красный — нарушение. Расчёт выполняет детерминированное
ядро, UI только отображает результат (RULES § 5.1).

### 7.5 Нативный Desktop (Tauri)

В `src-tauri` подключены плагины `tauri-plugin-dialog` и `tauri-plugin-fs`
(Rust), в `capabilities/default.json` выданы разрешения на чтение/запись
`*.vwc`. При запуске в Tauri (`isTauri()`) кнопки «Сохранить проект» и
«Открыть проект» открывают системные диалоги ОС и работают с локальным
файлом напрямую — без браузерного скачивания. В вебе остаётся обычный
`Blob` + `<a download>`. В шапке отображается индикатор «Офлайн (Tauri)».

## 9. Ограничения

- Длина кабеля и сечение не рассчитываются в UI; расчёт выполняет `calc-engine`.
- Undo/redo графа реализованы в v0.4.0 (`Ctrl+Z` / `Ctrl+Y`, кнопки в шапке).
  История живёт только в памяти сессии и не попадает в `.vwc`.
- KI-003: точки трассы хранятся в пикселях подложки при СИ-величинах графа.
- Эндпоинты `POST /projects/:id/ai/assemble-panel` и `/ai/audit-pue` описаны в
  UI-клиенте по контракту v0.2; серверная реализация агентов (срез S5 дизайна)
  готовится отдельно — до её появления кнопки ИИ возвращают ошибку API.
- KI-003 и KI-004 закрыты в v0.3.0: метрические `waypointsM` и живые цены
  каталога подключены; офлайн-режим Tauri использует локальный справочник.
- Эндпоинты `POST /projects/:id/import-cad` и `/short-circuit` описаны в
  UI-клиенте по контракту DESIGN v0.3; серверная реализация (срезы S3/S5)
  может отставать — до её появления кнопки возвращают ошибку API.
- DWG требует внешнего конвертера `ODA_CONVERTER_PATH`; DXF разбирается нативно.

## 10. Релиз v0.4.0: копилот, 3D-щит и комплект РД

### 10.1 Undo/Redo и демо-проекты

`editorStore.ts` хранит два стека снимков канонического графа: `past` и `future`
(до 50 записей). Любая мутация графа — расстановка ЭУИ, правка свойств,
трассировка, применение патча ИИ — фиксирует предыдущее состояние через
`commitGraph`. `undo()` возвращает последний снимок из `past` и переносит текущий
граф в `future`; `redo()` действует наоборот. Горячие клавиши `Ctrl+Z` и `Ctrl+Y`
(для macOS также `Cmd+Z` / `Cmd+Shift+Z`) обрабатываются в `App.tsx` и не
перехватываются полями ввода.

Меню «Демо-проекты / Шаблоны» в шапке открывает галерею из шести эталонных
кейсов золотого датасета — «Студия 230 В», «3-к квартира 400 В», «Дом ИЖС
с баней 80 м», «Офис 400 В», «Коттеджи 3ф 15 кВт», «2-к квартира (газ)».
Графы собираются детерминированно в `lib/demoProjects.ts`, проходят
`ProjectGraphSchema.parse` и доступны без сети (RULES § 5.4). Загрузка шаблона
также записывается в историю Undo. С v0.5.0 карточки показывают фазность
(1P 230 В / 3P 400 В), расчётную мощность и число групп, а в шапке проекта
отображается бейдж фазности загруженного шаблона.

### 10.2 ИИ-чат-копилот (`AiAssistantDrawer`)

Правая панель содержит ленту сообщений «Вы / ИИ-инженер», быстрые подсказки
(«Добавь мастер-выключатель», «Выдели духовой шкаф на отдельную линию»,
«Пересобери щит на КЭАЗ») и поле ввода. История сообщений живёт в сессии и
передаётся в `POST /projects/:id/ai/chat` полем `history`.

Если в ответе есть `proposedGraph`, показывается карточка «Предлагаемые
изменения» со списком `diffSummary` и кнопками «Применить к проекту» /
«Отклонить». Применение вызывает `editorStore.applyProposedGraph()`, который
валидирует граф и делает запись в стек Undo. При недоступности сервера
используется детерминированный локальный патч (`lib/aiChatLocal.ts`) без
вычисления физических величин (RULES § 5.1, § 5.4). Кнопки «Собрать щит с ИИ»
и «Аудит по ПУЭ-7» сохранены в блоке «Инструменты».

### 10.3 Пятая проекция — 3D-щит (`Panel3DView`)

Вкладка «3D-щит (НКУ)» строит сцену Three.js строго из `ProjectGraph`
(RULES § 5.2): корпус НКУ, DIN-рейки по 18 модулей, модули из `panelSlot` с
шириной `moduleWidthModules × 18 мм`, цветовая маркировка фаз, рычажки взвода,
маркировка QF/QD и шины N/PE. Доступны вращение и зум (`OrbitControls`), вид
спереди, сброс вида и переключение материала корпуса (металл/пластик). Клик
по модулю выделяет узел графа и открывает его свойства в инспекторе.

### 10.4 Комплект РД по ГОСТ (`gostPdfExport`, `GostDocsPanel`)

Кнопка «РД по ГОСТ» в шапке открывает форму реквизитов штампа: шифр проекта,
разработал, проверил, организация и стадия. Значения по умолчанию берутся из
`graph.stampMeta` (новое необязательное поле `ProjectGraphSchema`, обратно
совместимое с `.vwc` v2). Кнопка «Выпустить РД (PDF по ГОСТ)» формирует один
четырёхлистовой PDF A4:

1. Общие данные;
2. Однолинейная схема;
3. Компоновка щита НКУ;
4. Кабельный журнал и Спецификация оборудования.

Каждый лист имеет рамку и основную надпись по ГОСТ Р 21.101 с единой нумерацией.
Генерация полностью клиентская (`jsPDF` + Canvas для кириллицы), без обращений
к серверу — работает в офлайн-режиме Tauri.

### 10.5 Новые строки интерфейса

Все строки добавленных элементов (шапка, демо-кейсы, чат, 3D-вид, форма РД,
статусы Undo/Redo) вынесены в `src/i18n/ru.json` и `en.json`. Полнота ключей EN
по-прежнему проверяется на этапе компиляции через `TranslationKey`.

## 11. Релиз v0.5.0: lazy-чанк, шесть шаблонов и импорт DWG

### 11.1 Оптимизация бандла

`App.tsx` импортирует `Panel3DView` через `React.lazy` и динамический `import()`,
обёрнутый в `Suspense` со скелетоном (`panel3d.loading`). Именованный экспорт
компонента приводится к `default` в функциях загрузки. При наведении/фокусе на
вкладку «3D-щит (НКУ)» чанк предзагружается, чтобы переключение выглядело
мгновенным. Vite формирует отдельный файл `Panel3DView-*.js` (~544 КБ) с Three.js;
основной чанк уменьшается до ~799 КБ и укладывается в лист `chunkSizeWarningLimit: 800`.

### 11.2 Библиотека шаблонов

`demoProjects.ts` содержит шесть офлайн-шаблонов. Каждое описание помимо
`nameKey`/`descriptionKey` несёт `supply` (`'230' | '400'`), `powerKw` и `groups`.
Модальное окно шапки показывает карточки с бейджем фазности и параметрами;
текущий шаблон определяется по детерминированному `graph.id` через
`getDemoByGraphId()` и выделяется в галерее. Все шаблоны — проекции единого
`ProjectGraph` и работают в Tauri без сети.

### 11.3 Импорт чертежей

Инпут импорта принимает `.dxf` и `.dwg`. Пока API разбирает файл, в шапке
отображается спиннер и статус `cad.importing`. Ошибка `ApiClientError` разбирается:
если сообщение содержит признаки отсутствующего конвертера (ODA / DWG),
показывается локализованная подсказка и исходный текст ответа API; иначе —
префикс `cad.apiError` и сообщение сервера. Уведомление можно закрыть.

## 12. Релиз v0.6.0: многощитовые проекты и ВТХ

### 12.1 Активный щит

`uiStore.activePanelId` хранит выбранный щит только в сессии интерфейса: граф и
`.vwc` при переключении не меняются (RULES § 5.2). `PanelSelector` показывает
дерево щитов (`ВРУ`, `ЩР-1`, `ЩР-2`) и кнопку «Добавить распределительный щит».
Добавление через `editorStore.addDistributionPanel(parentPanelId)` создаёт узел
`kind: 'panel'` с `panelRole: 'sub_shr'`, `parentPanelId` и ребро
`edgeType: 'feeder_line'`; действие записывается в историю Undo.

Фильтрация проекций выполняется helper-функциями `lib/panelHierarchy.ts`:
`getPanels`, `resolveActivePanelId`, `getNodesForPanel`, `getEdgesForPanel`,
`getFeederEdges`. 2D-компоновка, 3D-сцена и однолинейная схема получают
отфильтрованное представление тех же узлов графа и показывают счётчик
входящих/отходящих магистралей. Схема дополнительно включает узлы смежных
щитов, чтобы были видны питающие и отходящие `feeder_line`.

### 12.2 График ВТХ

В инспекторе аппарата защиты с входящим ребром появляется кнопка
«Кривые селективности (ВТХ)». Компонент `TccCurveChart` строит SVG с
логарифмическими осями тока и времени, кривыми вышестоящего и нижестоящего
автоматов (B/C/D), вертикальной линией $I_{кз}^{(1)}$, маркером предела
селективности $I_s$ и бейджами статуса и отключающей способности $I_{cn}$.
Запрос идёт в `POST /projects/:id/selectivity-tcc`; при недоступности сервера
используется явно подписанный детерминированный предпросмотр `lib/tcc.ts`
(без участия LLM).

### 12.3 Шаблон 07 и генератор РД

В галерее добавлен седьмой кейс `twostory-house-vru-shr` с бейджем
«2 щита: ВРУ + ЩР-2». Генератор `gostPdfExport.ts` для многощитовых проектов
добавляет по два листа на щит (схема и компоновка) после базовых четырёх
листов; штамп и нумерация ведутся централизованно, всего листов =
$4 + 2 \times N_{щитов}$.
